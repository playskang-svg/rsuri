# 수리위키 프로젝트 인수인계서 (2026-09-01)

## 1. 개요
기존 Vite 기반의 SPA(`src/`)를 폐기하고, **Next.js (App Router) + Supabase** 기반의 정적 페이지 생성(pSEO) 구조로 개편 중입니다. 최근 작업에서는 관리자 페이지(`web/app/admin/page.tsx`) 내에 **'자유 지역 키워드 일괄 추가 기능'**을 통합했습니다.

## 2. 주요 작업 내용 (최근 변경 사항)

### 2.1 관리자 페이지 UI 개편 (`web/app/admin/page.tsx`)
- 기존의 지역(동) 드롭다운 선택 방식을 개선하여, 체크박스 기반 다중 선택 모달 패널로 업데이트되었습니다.
- **[신규 추가]** 해당 모달 하단에 **자유 지역명 입력 텍스트 영역(`<textarea>`)**을 추가했습니다.
- 엑셀이나 메모장에서 콤마(`,`) 또는 줄바꿈(`\n`)으로 구분된 지역명 목록(예: `천안 불당, 천안 두정`)을 복사해 붙여넣으면 한 번에 여러 개의 페이지 조합을 생성할 수 있습니다.

### 2.2 커스텀 지역 DB 연동 로직
- **로직 동작 방식 (`attachCustomRegions` 함수):**
  1. 관리자가 자유 텍스트로 입력한 지역명을 파싱합니다.
  2. `suri_regions` 테이블을 조회하여 해당 이름(`display_name`)이 존재하는지 확인합니다.
  3. 존재하지 않는 새로운 지역일 경우, 즉시 `suri_regions` 테이블에 **새 레코드(`level: 'CUSTOM'`, `slug: 'custom-[타임스탬프]'`)를 Insert** 합니다.
  4. 획득한 `region_id`와 수리명(`repair_keyword_id`)을 매칭하여 `suri_pages` 테이블에 최종 조합(`page_type: 'LANDING'`)을 저장합니다.

### 2.3 배포 파이프라인 연동
- 수리위키는 정적 Export 구조이므로, 조합을 추가한 뒤 실제 사이트에 반영하려면 **GitHub Actions 워크플로(Deploy)** 가 트리거되어야 합니다.
- 위 사항을 반영한 최신 코드는 현재 `main` 브랜치에 Merge 및 Push가 완료된 상태입니다.

## 3. 후속 작업 및 인계자 참고 사항
- **Supabase 스키마 유의:** 커스텀 지역 추가 시 생성되는 고유 슬러그 형식(`custom-{Date.now()}-...`)을 유지하도록 작성되었습니다. 필요 시 `slug` 명명 규칙을 운영 환경에 맞게 고도화할 수 있습니다.
- **OG 썸네일 이미지 및 WIKI 라우트:** 현재 WIKI 라우트는 임시 보류(`_pending/wiki/`) 처리되어 있으므로, 본격적인 지식형 페이지(CT2, CT3 등) 작성 시 라우트를 활성화해야 합니다 (`docs/PRD.md` 로드맵 참조).
